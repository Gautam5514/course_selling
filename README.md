# Gopo Workspace (helloS) — course platform

One repository, two apps:

| Folder | What | Stack | Deploys to |
| --- | --- | --- | --- |
| [`course_selling/`](course_selling/) | Website + admin panel | Next.js 16, React 19, Tailwind 4 | Vercel |
| [`backend/`](backend/) | REST API | Node 20, Express, MongoDB, Cloudinary | Render (or any Docker host) |

The site talks to the API over HTTPS with an httpOnly cookie session. Everything
students see (note cards, PDFs, code, Today Code, reviews) is managed from
`/admin` on the website and stored by the API.

## Run locally

Requirements: Node 20+, MongoDB running locally (or an Atlas URI).

```bash
# 1. API
cd backend
cp .env.example .env        # then set OWNER_PASSWORD (and Cloudinary keys if you have them)
npm install
npm run dev                 # http://localhost:5001  (health: /api/health)

# 2. Website (new terminal)
cd course_selling
cp .env.local.example .env.local
npm install
npm run dev                 # http://localhost:3000
```

Sign in at `http://localhost:3000/login` with `OWNER_EMAIL` / `OWNER_PASSWORD`
from `backend/.env`; that account is created as ADMIN on first boot and the
admin panel is at `/admin`.

## Deploy

Deploy the API first (you need its URL for the website), then the website,
then come back and allow the website's URL in the API's CORS list.

### 1. MongoDB Atlas

Create a free cluster, a database user, and allow access from anywhere
(`0.0.0.0/0`, Render's IPs are not fixed). Copy the connection string:
`mongodb+srv://<user>:<password>@<cluster>/course_lms?retryWrites=true&w=majority`.

### 2. API on Render

The repo contains [`render.yaml`](render.yaml), so: **Render → New → Blueprint →
select this repo**. Render creates the `course-api` web service from the
`backend/` folder and prompts for the secret values:

| Variable | Value |
| --- | --- |
| `MONGODB_URI` | the Atlas string above |
| `CORS_ORIGINS` | your website URL(s), comma separated, e.g. `https://gopo.vercel.app,https://www.gopo.in` |
| `OWNER_EMAIL` / `OWNER_PASSWORD` | the admin login (choose a strong password) |
| `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` | from the Cloudinary dashboard. Required in production: Render's disk is wiped on every deploy, so PDFs must live on Cloudinary |
| `FIREBASE_SERVICE_ACCOUNT_BASE64` | for Google sign-in: `base64 -i serviceAccount.json \| tr -d '\n'` of the Firebase Admin key (optional; leave empty to hide the Google button) |

`JWT_SECRET` is generated by Render, and `COOKIE_SECURE=true` /
`COOKIE_SAME_SITE=none` are preset because the website and API are on different
domains. After the first deploy open `https://<your-api>.onrender.com/api/health`
and check it answers `{"data":{"status":"ok",...,"storage":"cloudinary"}}`.

Without the blueprint (manual web service): Root Directory `backend`, Build
`npm ci --omit=dev`, Start `npm start`, Health check `/api/health`, and the same
environment variables as in [`backend/.env.example`](backend/.env.example).

Docker is also available: `docker build -t course-api ./backend` (see
[`backend/Dockerfile`](backend/Dockerfile)).

### 3. Website on Vercel

**Vercel → Add New Project → import this repo**, then in the project settings:

| Setting | Value |
| --- | --- |
| Root Directory | `course_selling` (required — the app is not at the repo root) |
| Framework | Next.js (auto-detected) |
| Environment variable | `NEXT_PUBLIC_API_URL` = `https://<your-api>.onrender.com` (no trailing slash) |
| Google sign-in (optional) | `NEXT_PUBLIC_FIREBASE_API_KEY`, `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`, `NEXT_PUBLIC_FIREBASE_PROJECT_ID`, `NEXT_PUBLIC_FIREBASE_APP_ID` from Firebase → Project settings → Your apps → Web. Also enable Google under Authentication → Sign-in method and add the Vercel domain under Authorized domains |

Deploy, then put the Vercel URL into the API's `CORS_ORIGINS` (Render →
Environment) and redeploy the API. Custom domains work the same way: add every
origin that will open the site.

### 4. Check it end to end

1. Open the site, sign in as the admin, create a note, upload a PDF, publish.
2. Open the note on the home page in a private window, sign up as a student, read the PDF, leave a review.
3. Post today's code in `/admin/daily-code` and open **Today Code** from the navbar.

## CI

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs on every push and
pull request: the API is syntax-checked and the website is linted and built.
Vercel and Render deploy automatically from `main`.
